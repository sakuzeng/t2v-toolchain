## 观察
- 首次运行"Requested to load MiniMaxH3TEModel_ → MiniMaxH3"，文本编码器与扩散模型不同时驻留，采样前有换入换出；模型驻留后第二次起应更快（待验证）。
- ComfyUI-Manager 启动时拉 GitHub 的节点列表超时报 ERROR，不影响生成，可忽略（或在 Manager 设置里改用镜像/关闭自动拉取）。
- 峰值显存（#2，`nvidia-smi -l 5` 旁路 102 采样）：32082 MiB 只出现 1 次（提交后约 20 s，文本编码器 15G 与扩散模型 20G 换入换出的瞬间），采样期稳定 21586 MiB，VAE 解码期 26.5G。说明 ComfyUI 动态加载把两个模型错开了，但换模瞬间几乎打满，任何常驻占显存的东西（浏览器、第二个进程）都可能触发 OOM。
- 模型驻留后第二条并没有更快：#2 仍有 43 s 的首步初始化（含换模），"驻留后更快"未被证实。
- 抽帧拼图原在 `projects/smoke/outputs/02_768p_frames.png`（2026-09-18 已清除）。
- R2V（#5）480p 稳态显存 27.3G，比 T2V 480p 高约 6G；采样 7.3 s/步 vs T2V 480p 6.8 s/步。
- **显存结论（#6，2026-09-06）**：ComfyUI 在 torch 2.8 + NVIDIA 上默认开动态显存加载（日志 `prepared for dynamic VRAM loading … Staged`），权重按需分块进显存、放不下的留在内存（本机 92G），所以 `nvidia-smi` 看到的占用是「有多少用多少」，同一任务在不同时刻可以 28G 也可以 21G。**5090 上 R2V 768p 直接跑即可，不必先降分辨率。** 若真 OOM，按顺序试：`--disable-pinned-memory`（社区反馈可降内存/修复加载慢）→ `--reserve-vram 2` → `--lowvram`；参考图 `ref_image_size=match`（默认）比 `max` 省很多 token。1080p 未测。
