# docs 索引

按**文档的身份**分目录，不按主题分：同一个主题（比如 Blender）可能同时有"要照着做的规范"和"某天的调研结论"，
它们的更新节奏和可信度不同，必须分开放。

| 目录 | 身份 | 里面是什么 | 什么时候动它 |
|---|---|---|---|
| `guide/` | **常青规范与手册**，写的是"现在该怎么做" | 见下表 | 做法变了就改写原文，不追加 |
| `research/` | **调研快照**，写的是"某天我们查到了什么" | 一题一文，文首标日期 | 新调研新增文件；结论被推翻时在文首加更新块，**不删原文** |
| `ops/` | **运维事实** | `PITFALLS.md` 踩坑（现象→原因→解法）；`BASELINE.md` GPU 基线（每条测试一行） | 遇坑必记；每次冒烟/基线后 |

> 原工作台另有 `plan/`（总计划与验收）、`status/`（实例台账与当前状态）、`reference/`（官方原文捕获）
> 三个目录，属于私有运行态，未随本仓分发。

## `guide/` —— 要照着做的

| 文件 | 管什么 |
|---|---|
| `PROJECT_SYSTEM.md` | 项目目录结构、配置分层、run capsule、命名、标准流程与迁移原则 |
| `H3_PROMPT.md` | H3 三段式 / R2V 六段式的字段与语法；校验方式；prompt 文件用 `.md` + `.zh.md` 的约定 |
| `COMFYUI.md` | 官方工作流模板、程序化驱动的接口、插件取舍、浏览器访问（含实验室容器版隧道）、配套 skill 分工 |
| `MODELS.md` | 权重手册：H3 的 17 个文件各自干什么、谁加载它、体积档为什么这么选；另附 FLUX.2 klein 生图权重 |

工作流 JSON 本身在仓库根 `workflows/`；`t2v` 包的命令表与模块分层在 `t2v/README.md`。

## `research/` —— 某天查到的

一题一文，文首标日期。结论被后来的实测推翻时，在文首加"结论更新"块并说明证据，正文保留——
调研文档是**当时的判断记录**，不是现行规范；现行规范在 `guide/`。

| 文件 | 题目 |
|---|---|
| `ACCEL.md` | 加速方案取舍（SageAttention / 缓存 / Turbo LoRA） |
| `VRAM.md` | 5090 上显存不是瓶颈的依据与 OOM 处理顺序 |
| `H3_PROMPT_PATTERNS.md` | 官方范例与社区经验里好 prompt 的写法、密度上限 |
| `CAMERA_REPLICATION.md` | 借参考片运镜的四条路线取舍（**路线 A 深度控制已于 2026-09-16 否决**，见文首更新块） |
| `MOTION_TRANSFER.md` | 深度控制失败后的动作迁移路线（SCAIL-2 / Wan Animate）、权重与磁盘预算、止损门 |

## 边界

**项目级知识不放这里**：作品的设定、分镜和决策写在 `projects/<项目>/creative/`，运行事实写 `runs/index.jsonl`，
项目状态、阻塞和下一步只写 `projects/<项目>/PROGRESS.md`。`docs/` 只放跨项目的链路知识，
`status/STATUS.md` 不记录具体镜头版本、评审或生成费用。

**通用经验不放这里**：跨项目通用的 AutoDL 经验回写到 `~/improve/coding/autodl/docs/`，这里只留本链路特有的。

命名：文件名大写单词；同一主题只保留一份，过时内容改写而不是追加副本。
